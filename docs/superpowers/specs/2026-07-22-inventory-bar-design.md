# 屏幕物品栏贴图化设计

## 目标

在屏幕底部中间显示本地玩家的四个普通物品槽位，使用 `resource` 中与物品类型和等级对应的贴图代替中文物品名称，同时保留键位数字和当前手持高光。发布形式继续保持单 EXE，不依赖外部资源目录。

## 界面

- 功能默认关闭。
- 使用透明、无装饰 ImGui 窗口绘制四个槽位。
- 每格固定正方形，默认 36×36px。
- 键位 1、2、3、4 显示在对应槽位左上角，并绘制在贴图上层。
- 非空槽在边框内等比例居中绘制对应物品贴图，不再显示中文名称。
- 空槽只显示键位数字。
- 普通槽使用半透明细边框；当前手持槽使用较粗的高光边框。
- 高光颜色可设置，默认白色。

## 位置和方向

- 默认位于屏幕底部中间，保持横向布局。
- 未固定且游戏处于前台时，按住 Alt 可拖动。
- 距离左侧或右侧 24px 内切换为纵向。
- 距离顶部或底部 24px 内保持或切换为横向。
- 角落同时满足横向和纵向条件时，横向优先。
- 布局切换后保持窗口中心并约束到屏幕范围内。
- 保存窗口位置和设置。

## 数据读取

- 复用 `PCPropGrab.Update` 的统一游戏线程调度器，不安装第二个同入口 Hook。
- 从 `PCPropGrab + 0x50` 读取 `List<PhotonObjectInteract>` 作为四个普通槽位候选。
- 从 `PCPropGrab + 0x48` 获取 `NetworkedPropGrab`，动态调用 `get_HeldObject()` 获取当前手持对象。
- 将当前手持对象与四个槽位对象逐一比较，确定高光槽位。
- 每个槽位沿 `PhotonObjectInteract → Prop → Equipment → StoreItem` 解析 `equipmentType` 和 `tier`。
- `equipmentType` 有效范围为 0–20，`tier` 有效范围为 0–2；二者共同索引 63 张贴图。
- 游戏线程只发布四组 `equipmentType/tier` 和当前索引的纯值快照；渲染线程不持有 Unity 对象指针。

## 贴图资源

- 使用现有 `resource` 目录中的 63 张 PNG，覆盖 21 种物品及各自三级贴图。
- 通过显式资源表建立 `equipmentType/tier` 与文件的对应关系，不依赖大小写不一致的文件名运行时拼接。
- 构建阶段将 PNG 转换成 C++ 字节数组并编入 payload；注入器继续将 payload 内嵌到单 EXE。
- Overlay 获取 D3D11 设备后，从内嵌 PNG 创建 `ID3D11ShaderResourceView`。
- 纹理只在渲染线程创建、使用和释放。
- Overlay 关闭时释放全部 Shader Resource View。
- PNG 解码使用 Windows Imaging Component，链接 `windowscodecs`，不引入额外第三方图片库。

## 绘制流程

1. 游戏线程采集四槽 `equipmentType/tier` 快照。
2. 渲染线程按 `(equipmentType * 3 + tier)` 获取纹理。
3. 在槽位边框内留出少量内边距，将贴图等比例居中绘制。
4. 在贴图上层绘制 1–4 键位数字。
5. 最后绘制普通或当前手持高光边框，保证边框清晰。

## 设置与配置

保留现有设置：

- 启用：默认关闭。
- 固定：默认关闭。
- 槽位大小：默认 36px。
- 字体大小：继续用于键位数字及现有配置兼容。
- 高光颜色：默认白色。
- 窗口位置与布局。

本次不新增持久化字段，无需升级配置版本。

## 失败处理

- 列表不存在、长度异常或对象无法解析时，不显示猜测贴图。
- `equipmentType` 或 `tier` 越界时，对应槽位保持空白，不回退为物品名称。
- 单张贴图解码或纹理创建失败时记录一次日志，其余贴图继续加载。
- 四个槽位框和键位仍正常绘制和拖动。
- 当前手持对象无法与槽位匹配时，不高光任何槽位。
- 相机专用槽不纳入四格物品栏。

## 验证

- 纯逻辑测试覆盖资源索引边界、自动方向、角落横向优先和当前对象槽位匹配。
- 验证 21 种物品的 0–2 级均映射到正确内嵌资源。
- Debug、Release 构建和 CTest 均通过。
- 游戏内验证拾取顺序、不同等级贴图、按键切换、丢弃中间槽位、无手持物及相机专用槽排除。
- 验证仅携带最终注入器 EXE 时贴图可正常显示。
